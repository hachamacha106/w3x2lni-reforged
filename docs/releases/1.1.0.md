## Analyze and lossless archive optimization

Drop a map into the GUI and choose **Analyze map** to inspect its largest members,
stored and decoded sizes, identical contents, import problems, archive eligibility
and independent JASS verification. You can also drop a folder produced by **To
LNI**, or its `.w3x` marker. Folder analysis reports exported file sizes,
identical contents, import problems and JASS verification without assembling or
changing the project. Converted tables and triggers remain project files;
compressed archive sizes and archive optimization apply only to packed maps.
Choose the actual `.w3x`/`.w3m` file for Optimize; adding an extension to the
output name does not turn an LNI input folder into an archive. The GUI explains
this restriction before starting and keeps folder analysis/conversion available.
If archive inspection cannot finish, Analyze reports the readable content and
incomplete inventory; that map remains ineligible for optimization.

Choose **Optimize archive**, review or edit the full output path, then click
**Start**. The suggested path is a new `<map>.optimized.w3x` (or `.w3m`) beside
the input. The output folder must already exist. This avoids the retained
runtime's native Save As dialog, which can fail to open on some Windows systems.
Returning from the report keeps the chosen path; selecting another input supplies
a fresh default. Use **Cancel operation** to request cleanup and stop the new
archive action; closing its GUI also requests cancellation. Forced process
termination can leave a temporary candidate folder, while the source remains
untouched. If startup or a worker fails, current diagnostics remain available
through **Report** and **Copy all**.
Existing files and the source map are never overwritten. The tool compares
512-byte, 4 KiB and 64 KiB archive sectors, reopens candidates and compares every
payload byte. Only a verified, smaller candidate becomes the output. No savings
means no output map; the report explains the result. StormLib 9.40 rejects the
512-byte sector layout, which is reported as unsupported; only the reopened
4 KiB and 64 KiB candidates can be accepted.

The initial optimizer supports understood ordinary MPQ v1 .w3x/.w3m archives up to
256 MiB. Peak memory can be substantially higher than the input size because
raw, decoded and candidate bytes coexist in the x86 process. Large-map speed
and memory benchmarks remain required before expanding this limit. It preserves the standard outer map header, file names, every payload,
and internal listfile/attributes bytes. Inventory parsing is limited to 65,536
hash entries and a 16 MiB listfile in this first implementation. Unknown flags, incomplete discovery,
additional locales, encryption, signatures, orphan/aliased blocks, malformed
metadata and unexplained container bytes are reported without rewriting.
Sector CRCs, PKWARE/bzip2 compression and encrypted internal bookkeeping also
remain analysis-only in this first optimizer.
Textures, models, audio, object records, editor files and scripts are unchanged.

CLI:
~~~
w2l.exe analyze input.w3x
w2l.exe analyze "My exported LNI folder"
w2l.exe optimize input.w3x new-output.w3x
~~~

## Independent, report-only JASS verification

The pinned pjass helper checks the actual JASS script against common.j and
blizzard.j from the selected Warcraft dataset. Input and final converted scripts
are checked separately. Results include Passed, Failed, Unavailable and Skipped;
Lua maps are skipped. Map-supplied declaration replacements get a separate result.
Failures are visible but do not block output, repair scripts or alter conversion
exit status. A failed, suppressed or unavailable check is never labeled Passed.
Syntax/declaration checking does not establish gameplay correctness.

## Native dependency provenance

The new Actions path builds Windows x86 Unicode StormLib 9.40 against static zlib
1.3.2 from exact pinned source commits. Its ABI/storage probe, settings, compiler
and hashes accompany the artifact. Only that verified StormLib DLL may replace
the upstream file. The other 21 upstream native files retain byte verification.
The pinned upstream pjass release is an added helper with its own checksum.
BUILD_INFO.json distinguishes these origins; NATIVE_BUILD.json and NATIVE_ABI.json
retain build and ABI evidence. No binaries or release artifacts belong in Git.

CascLib and the remaining original runtime are retained. Its source still uses
its own older zlib copy; updating it needs a separate real-game extraction check.

## Local development checks — 2026-10-09

Twenty Python safeguard tests and all fourteen locally executable Lua
compatibility suites passed. Native Windows integration exercised real pjass,
all four existing conversions, invalid-JASS report-only conversion, live FFI,
Unicode Analyze/Optimize, cancellation, races and exact payload preservation.

**test-only** StormLib 9.40 DLL; that DLL is excluded from release packaging.

ZIP execution and manual GUI/World Editor/game acceptance remain pending. No
